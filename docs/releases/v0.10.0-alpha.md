# v0.10.0-alpha

This alpha release packages the framework convergence and case-study work
landed after `v0.9.0-alpha`.

Use it when a campaign needs manual seeds, separate planning and coding model
routes, evaluator-defined candidate identities, reusable phased measurements,
or evaluator capacity that is independent of search and model-worker
concurrency.

## Highlights

- First-class manual-seed manifests import remotely pinned, direct-child
  commits as normal archive-eligible jobs. They skip planning, coding, and
  trajectory model calls while retaining the configured scope gate, evaluator,
  provenance, measurement cache, and archive ingestion.
- The public `phased-v1` evaluator protocol separates source preparation,
  reusable measurement, and finalization. Accepted measurement reuse is scoped
  by evaluator, campaign, target-defined identity, and a canonical measurement
  contract fingerprint.
- PostgreSQL-backed evaluator capacity `E` is independent of the scheduler's
  unfinished-job limit `U` and the local worker-process count `W`. Slot wait,
  acquisition, and release evidence is persisted.
- Campaign progress distinguishes physical jobs, passed Git trees,
  evaluator identities, real measurements, measurement reuse, archive entries,
  and occupied coordinates. An optional unique-identity endpoint stops new
  dispatch and drains existing work.
- Planning, coding, and trajectory summaries have explicit model routes.
  Commit messages reuse the coding or planning summary and no longer require a
  separate model request.
- Evaluator authors can use fixed-sample and anytime-valid intervals,
  preweighted stratified estimates, bounded adaptive sampling, resumable
  checkpoints, and canonical measurement-contract fingerprints.

## Upgrade Notes

### Database migration required

This release bumps `INSTANCE_SCHEMA_VERSION` from 15 to 21. Back up a
non-disposable PostgreSQL database, stop schedulers and workers, then run:

```bash
uv run loreley db migrate
uv run loreley db validate
```

The migration chain adds:

1. schema 16 evaluator-provided candidate identities;
2. schema 17 restart-stable sampling recipes and exact Git-tree identities;
3. schema 18 complete bounded change summaries;
4. schema 19 phased measurements, evaluator concurrency contracts, leases, and
   stable failure fields;
5. schema 20 staged supplied-candidate jobs used by manual seeds; and
6. schema 21 append-only evaluation attempts and artifact evidence.

The chain preserves existing jobs, candidate commits, metrics, artifacts, and
archive state. Migration is idempotent. With `DB_AUTO_MIGRATE=true`, normal
process startup applies the same chain, but an explicit backup and migration is
recommended for a controlled upgrade.

### Configuration review

Existing one-shot evaluator plugins remain supported. The new controls are
inactive unless configured, except that an optimization campaign using a
`local-hash*` embedding fixture must now explicitly set
`MAPELITES_LOCAL_HASH_EMBEDDING_ACKNOWLEDGED=true`.

Review these settings before starting a new campaign:

- `WORKER_PLANNING_BACKEND` and the phase-specific planning model settings;
- `WORKER_CODING_BACKEND` and the phase-specific coding model settings;
- `WORKER_PLANNING_TRAJECTORY_SUMMARY_*` when trajectory summaries are enabled;
- `WORKER_EVALUATOR_VERSION` whenever evaluator semantics or benchmark data
  change without a plugin source change;
- optional `WORKER_EVALUATOR_MAX_CONCURRENCY` for evaluator capacity `E`; and
- optional `SCHEDULER_MAX_UNIQUE_EVALUATION_IDENTITIES` for an identity-based
  endpoint.

Run `loreley doctor --role worker` and `loreley config dump` before a campaign
to inspect the effective secret-free routes and concurrency controls.

### Manual seeds

Publish each seed under a stable full Git ref, then import the complete manifest
while the scheduler is stopped:

```bash
uv run loreley seeds import seeds.yaml
```

Imported seeds are staged atomically and promoted in manifest order without
raising `U`. See the [manual-seed guide](../loreley/manual-seeds.md) for the
manifest contract and remote-ref requirements.

## Added

- Per-job Kilo state isolation and optional `kilo run --pure` support, including
  preflight capability checks.
- Phase-specific Kilo planning and coding models, plus explicit provider,
  thinking, and reasoning controls for trajectory summaries.
- Evaluator-provided candidate identities and exact Git-tree identities for
  archive deduplication and contract-scoped result reuse.
- Hash-linked measurement provenance and append-only evaluation evidence across
  retries.
- Secret-free route diagnostics and explicit acknowledgement for non-semantic
  local-hash embedding fixtures.
- A [64-job `markdown-it-py` case study](../research/2026-08-02-markdown-it-py-deepseek-case-study.md)
  with a separately validated 6.75% throughput improvement.
- A [64-job `python-pathspec` case study](../research/2026-08-03-pathspec-deepseek-case-study.md)
  documenting a four-generation 25.14% diagnostic candidate and the
  allocation-selection failure that invalidated the preregistered outcome.
- A [fresh Zstandard V19 case study](../research/2026-08-07-zstandard-gpt-v19-case-study-report.md)
  whose registered winner improved sealed-holdout compression by 1.02% with
  neutral decompression, plus a separately registered Top-10 follow-up.
- A [three-case-study evidence report](../research/2026-08-07-loreley-case-study-evidence-report.md)
  that keeps prospective, post-hoc, and supplemental results distinct.

## Fixed

- Include descendant Kilo sessions and reasoning output in usage accounting
  without double counting descendant sessions.
- Read Kilo tokens and cost from its session tree, classify catalog dollars
  separately from provider-billed spend, and avoid local price reconstruction.
- Keep native-provider Kilo workers non-interactive by disabling interactive
  and suggestion tools in the injected headless profile.
- Preserve bounded token and request failure codes through agent retries.
- Fetch candidate commits explicitly when narrow clone refspecs omit their
  branches.
- Terminate complete Kilo and evaluator process groups on timeout so descendant
  requests, builds, and benchmarks do not survive their owning job.
- Derive sampling from persistent per-island ordinals and cool down recent
  `(base, inspirations)` recipes across scheduler restarts.
- Verify stored measurement evidence before cache acceptance and reuse.
- Evaluate manual seeds in detached checkouts without fabricating a worker
  branch or publication record.
- Declare the CLI's direct `click` dependency, expose the installed distribution
  version from optional API and UI packages, and restore package author,
  license, keyword, and classifier metadata.

  three versions.

Build the wheel and source distribution from a clean checkout. Install the same
wheel into clean Python 3.11, 3.12, and 3.13 environments, verify the installed
version exposed by `loreley.api` and `loreley.ui`, and run `loreley --help`.
The source distribution is limited to installable source and build metadata so
historical experiment artifacts cannot enter the package. Do not publish
artifacts built from a dirty worktree.
